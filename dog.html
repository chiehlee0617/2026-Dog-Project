[專案一-1] AI Agent —— 歷史 PPT 與 GraphRAG 建置
把散落的結案報告轉化為結構化知識圖譜

❌ 傳統痛點與瓶頸

歷史經驗碎片化
重大 Dog 異常結案報告 (PPT) 散落各處，內含寶貴的 Issue、Root Cause 與 Playbook，但全為非結構化文字。
經驗傳承成本高
新進工程師面對重複發生的機台異常，往往需要耗費大量時間翻閱舊檔案或靠口耳相傳。

✨ GraphRAG 解決方案

自動化知識圖譜化
自動吞噬過去一年重大 Dog 結案報告，萃取核心因果關係並建立檢索圖譜。
智慧查詢與對應
系統能主動推薦：「當發生特定 Issue 時，歷史上通常有哪些標準查案手法 (Playbook)」。
[專案一-2] AI Agent —— DAO 映射與 Mapping 機制實作
現階段實戰做法與 LLM 學習驗證

🛠️ 現階段實作方式

實戰導向的 LLM 學習法
目前尚未建立龐大 Wiki，而是將系統內的 DAO 名稱、Input/Output 格式與欄位定義，直接與歷史查案手法一同餵給 LLM。
關聯對應建立
讓模型自主學習並建立「查案需求 ➔ 對應 DAO 呼叫」之間的對應關係，加速自動化進程。

⚠️ 面臨挑戰與下一步

半導體加密欄位考驗
資料庫欄位代碼加密過深，直接交由 LLM 學習會面臨語意對齊與準確度挑戰。
持續優化與評估
持續優化 Prompt 結構，並逐步導入人工驗證機制，確保 Agent 推薦結果 100% 可靠。
[專案二] systemxx 系統 —— 資料斷點自動化診斷邏輯
從手動追蹤數百行 SQL，到 API 驅動的智慧斷點排查

🔍 斷點自動診斷原理

As-Is 傳統痛點
使用者回報系統沒看到資料時，工程師需人工回溯數百行複雜 Loader SQL，逐段檢查在哪個條件判斷式被過濾。
To-Be 自動化改善
開發自動化診斷 API，自動模擬資料流向與條件判斷，精準回報資料是在哪一個步驟因為不符合條件而中斷。

📊 診斷 API 自動化檢索流程

1. User 回報：systemxx 無近點資料
↓
2. Query 該時間區間是否有進站/過貨紀錄？
否 → 【斷點】時間區間無進站資料
↓ 是
3. 檢查是否有該項目的量測/FDC紀錄？
否 → 【斷點】未量測或未觸發參數
↓ 是
4. 跑 Loader SQL 條件判定式過濾
↓
5. 精準定位：回傳被哪一行 SQL 條件過濾
